## 1. 事务传播行为

- REQUIRED：默认，存在事务则加入，否则新建。
- REQUIRES_NEW：总是新建，挂起外层事务。
- NESTED：在当前事务内创建保存点。
- SUPPORTS/NOT_SUPPORTED/NEVER/MANDATORY：按需参与或禁止事务。

## 2. 回滚规则

- 默认仅对 `RuntimeException` 和 `Error` 回滚。
- 使用 `@Transactional(rollbackFor=...)` 控制受检异常回滚。
- 可配置 `noRollbackFor` 例外。

## 3. 常见追问/易错点

- 追问：嵌套事务与新事务在回滚时的差异？
  - 答：核心结论是：Spring 通过事务传播行为决定是否复用或新建事务，默认在运行时异常时回滚，可通过 `rollbackFor` 等规则精细控制。展开时可按“事务传播行为、回滚规则”组织，先概述再逐点展开，保证结构完整。其中事务传播行为侧重REQUIRED：默认，存在事务则加入，否则新建，回滚规则侧重默认仅对 `RuntimeException` 和 `Error` 回滚。回答时要体现步骤、关键点与适用场景，必要时补充示例或对比。
- 易错点：在方法内部捕获异常导致事务不回滚。
  - 答：常见易错点是只给结论不讲依据、边界条件与前提不清。比如事务传播行为中提到：REQUIRED：默认，存在事务则加入，否则新建。回滚规则中还提到：默认仅对 `RuntimeException` 和 `Error` 回滚。这些细节很容易被忽视。回答时应明确边界、关键步骤与适用场景，并用实例或对比验证。
