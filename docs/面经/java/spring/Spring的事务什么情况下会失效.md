## 1. `@Transactional` 生效的前提

Spring 事务通常通过 AOP 代理实现，因此要先满足两个核心前提：

1. 目标对象必须是 Spring 容器管理的 Bean。
2. 方法调用必须**经过代理对象**（代理才能在调用前后开启/提交/回滚事务）。

很多“事务失效”并不是事务机制坏了，而是调用链绕开了代理或不满足增强条件。

## 2. 常见失效场景

### 2.1 同类内部自调用（最常见）

同一个类里，方法 A 调用方法 B（B 标注了 `@Transactional`），如果是 `this.b()` 这种调用，**不会走代理**，事务不会生效。

解决思路：

- 把 B 抽到另一个 Bean，通过注入调用。
- 或注入自身代理（不推荐滥用），通过代理调用。

### 2.2 方法签名不满足代理增强

常见限制（取决于代理方式）：

- `private` 方法通常无法被代理增强。
- `final` 方法/类在 CGLIB 代理下也无法覆盖增强。
- 如果使用 JDK 动态代理，只能代理接口方法；实现类独有方法不会被增强。

### 2.3 异常被捕获吞掉，导致不回滚

事务切面通常根据“方法是否抛异常”决定回滚：

- 你 `try/catch` 把异常吞掉，代理看到的是“正常返回”，就会提交。
- 受检异常默认不回滚，需要 `rollbackFor` 配置。

### 2.4 多数据源/多事务管理器配置错误

多数据源场景要确认：

- 使用了正确的 `PlatformTransactionManager`。
- `@Transactional(transactionManager = "...")` 指向正确 bean。

### 2.5 异步/多线程导致事务上下文丢失

Spring 事务上下文通常绑定在当前线程（`ThreadLocal`）：

- `@Async` 或手动开线程执行的代码，不会继承原线程事务。
- 需要用消息/补偿/显式事务边界来设计跨线程一致性。
