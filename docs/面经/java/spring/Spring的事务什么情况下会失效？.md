## 1. 常见失效场景

- 同类内部方法自调用，未经过代理。
- 方法非 public 或 final，无法被代理增强。
- 异常被捕获并吞掉，导致事务不回滚。
- `@Transactional` 放在接口且使用 JDK 动态代理但实现类未生效。
- 多数据源下使用了错误的事务管理器。

## 2. 解决思路

- 通过 Spring 容器获取代理对象调用。
- 使用构造器注入/拆分服务，避免自调用。
- 配置正确的 `TransactionManager` 与回滚规则。

## 3. 常见追问/易错点

- 追问：为什么在同一个类里调用事务方法会失效？
  - 答：核心结论是：事务失效多由 AOP 代理失效或调用方式不正确导致，如自调用、非 public 方法、异常被吞、使用了错误的事务管理器等。展开时可按“常见失效场景、解决思路”组织，先概述再逐点展开，保证结构完整。其中常见失效场景侧重同类内部方法自调用，未经过代理，解决思路侧重通过 Spring 容器获取代理对象调用。回答时要体现步骤、关键点与适用场景，必要时补充示例或对比。
- 易错点：在异常处理处吞异常导致“看似成功但未回滚”。
  - 答：常见易错点是只给结论不讲依据、边界条件与前提不清。比如常见失效场景中提到：同类内部方法自调用，未经过代理。解决思路中还提到：通过 Spring 容器获取代理对象调用。这些细节很容易被忽视。回答时应明确边界、关键步骤与适用场景，并用实例或对比验证。
