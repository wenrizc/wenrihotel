# Java 原生线程与线程池区别及常见坑

## 1. 核心区别
| 维度 | 原生线程 | 线程池 |
| --- | --- | --- |
| 创建与销毁 | 每个任务新建 | 线程复用 |
| 资源成本 | 栈内存与切换开销大 | 开销可控 |
| 控制能力 | 分散、难统一管理 | 统一限流与监控 |
| 适用场景 | 少量、短周期任务 | 大量、频繁任务 |

## 2. 线程池工作流程
线程池通过 `corePoolSize`、`maximumPoolSize`、`workQueue` 和拒绝策略控制任务执行。提交任务后，先使用核心线程处理，核心满了进入队列，队列满了再创建非核心线程，直到达到最大线程数。再超载则触发拒绝策略，由调用方处理或直接失败。

## 3. 线程池常见坑
高并发场景下最容易出问题的点如下。

- 使用 `Executors.newFixedThreadPool` 等工厂方法，默认无界队列导致 OOM 或延迟堆积。
- 同一线程池同时跑长耗时与短任务，导致关键任务被阻塞。
- 未设置超时与拒绝策略，异常流量下请求全部堆积。
- `ThreadLocal` 未清理，在线程复用时造成上下文串扰或内存泄漏。
- 业务线程里同步等待同池任务结果，可能触发线程池内死锁。

## 4. 实践建议
推荐从容量规划、隔离与监控三个方向入手。

- CPU 密集型建议线程数接近 `CPU 核数`，IO 密集型可适度放大。
- 使用 `ThreadPoolExecutor` 显式指定有界队列与自定义 `ThreadFactory`。
- 通过指标监控队列长度、活跃线程数与拒绝次数，及时告警。

## 5. 常见追问/易错点
面试中常被追问的点如下。

- 追问：为什么不推荐使用 `Executors` 直接创建线程池？
  - 答：默认策略可能是无界队列或无界线程，容易在高并发下出现内存或线程资源耗尽。
