## 1. 从源码到字节码：`javac` 做了什么

Java 源码（`.java`）不会被 JVM 直接执行，第一步是通过 `javac` 编译生成 `.class` 字节码文件。字节码文件中包含：

- 常量池（Constant Pool）：字符串字面量、符号引用等。
- 方法字节码：JVM 指令序列（栈式指令集）。
- 类/字段/方法的元信息：访问标志、描述符等。

### 1.1 用 `javap` 观察字节码

```bash
javac Hello.java
javap -c -v Hello.class
```

通过 `javap` 看到的“指令”就是解释器/JIT 的输入。

## 2. 类加载到可用：加载、链接、初始化

JVM 把 `.class` 变成可执行的类，需要经历类加载过程。

### 2.1 加载（Loading）

- 找到并读取类的二进制字节流（文件、网络、加密包等）。
- 在方法区/元空间创建类元数据结构，并在堆上创建对应的 `java.lang.Class` 对象。

### 2.2 链接（Linking）

链接包含三步：

1. **验证（Verification）**：校验字节码是否符合规范，确保类型安全。
2. **准备（Preparation）**：为类变量（`static`）分配内存并设置默认值。
3. **解析（Resolution）**：将常量池中的符号引用解析为直接引用（可延迟到首次使用）。

### 2.3 初始化（Initialization）

执行类初始化方法 `<clinit>()`，完成 `static` 变量赋值与静态代码块执行。注意初始化遵循“主动使用”触发规则（例如 `new`、访问静态字段/方法、反射等）。

## 3. 执行：解释器与 JIT（热点编译）

类准备好后，执行引擎开始运行字节码。HotSpot 常见是“解释执行 + 热点编译”的混合模式：

- **解释器（Interpreter）**：逐条解释字节码执行，启动快，但单次执行慢。
- **即时编译器（JIT）**：识别热点方法/循环，把字节码编译为机器码，执行快，但编译有成本。

### 3.1 热点探测与典型优化

JIT 会基于运行时 profiling 数据进行优化，例如：

- 方法内联（Inlining）
- 逃逸分析与标量替换
- 锁消除/锁粗化

当假设不再成立时，会触发反优化（Deoptimization），回退到解释执行以保证语义正确。

## 4. 运行期内存与 GC

程序运行过程中会不断创建对象，内存主要分布在：

- **堆**：对象实例与数组。
- **虚拟机栈**：栈帧、局部变量表、操作数栈。
- **元空间/方法区**：类元数据、常量、JIT 产物等。

GC 在运行期根据触发条件（分配失败、阈值、显式触发等）回收不再可达对象，并可能伴随停顿（Stop-The-World）。

## 5. 观测与排查（面试加分）

面试中能把“过程”落地到工具，会显得更工程化：

```bash
jcmd <pid> VM.flags
jcmd <pid> GC.heap_info
jcmd <pid> Thread.print
jstat -gcutil <pid> 1000
```
