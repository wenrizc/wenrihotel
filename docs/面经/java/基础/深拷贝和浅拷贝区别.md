## 1. 浅拷贝（Shallow Copy）

浅拷贝会创建一个新对象，然后将原始对象中的所有字段的值，原封不动地复制到新对象中。

- 对于基本数据类型（如 `int`、`double`、`boolean`），浅拷贝会直接复制它们的值。修改新对象的基本类型字段，不会影响原始对象。

- 对于引用数据类型（如 `String`、数组、或其他自定义对象），浅拷贝只会复制引用本身，而不会复制引用指向的对象。

这就导致一个关键结果：原始对象和浅拷贝出的新对象，其内部的引用类型成员变量，指向的是堆内存中同一个对象。

## 2. 深拷贝（Deep Copy）

深拷贝为了解决浅拷贝的问题而产生。它同样会创建一个新对象，但在处理引用类型成员变量时，它不是简单地复制引用地址，而是会递归地创建所有引用对象的新副本。

- 对于基本数据类型，深拷贝和浅拷贝的行为是一样的，都是值复制。

- 对于引用数据类型，深拷贝会创建一个新的、与原始对象内容相同的对象，然后将新对象的引用地址赋给拷贝出对象的成员变量。

这样做的结果是：原始对象和深拷贝出的新对象，它们内部的所有引用类型成员，都指向各自独立的对象。

| 特性 | 浅拷贝（Shallow Copy） | 深拷贝（Deep Copy） |
| --- | --- | --- |
| 基本类型 | 复制值 | 复制值 |
| 引用类型 | 复制引用 | 递归复制对象内容 |
| 对象关系 | 共享可变成员对象 | 成员对象相互独立 |
| 隔离性 | 差：改一处可能影响另一处 | 好：对象图相互隔离 |

## 3. 实现方式

1. 实现浅拷贝：

    - 最常见的方式是实现 `Cloneable` 接口，并重写 `Object` 的 `clone()` 方法。`Object.clone()` 的默认语义是浅拷贝。

2. 实现深拷贝：

    - 重写 `clone()`：在调用 `super.clone()` 得到浅拷贝对象后，再对可变引用成员逐个创建副本，形成真正的深拷贝。这要求所有可变成员都能被正确复制。

    - 通过序列化：把对象写入字节流再读出，得到一份新的对象图。所有对象都需要实现 `Serializable`，代码简单但 CPU 与内存开销更大。

## 4. Java 中的“拷贝”落地方式（怎么写更靠谱）

### 4.1 `clone()`：默认浅拷贝，深拷贝需要手动补齐

```java
class Address {
    String city;
    Address(String city) { this.city = city; }
    Address(Address other) { this.city = other.city; } // 不可变字段可直接复用
}

class User implements Cloneable {
    int age;
    Address address;

    @Override
    protected User clone() throws CloneNotSupportedException {
        User copy = (User) super.clone(); // 默认浅拷贝
        copy.address = new Address(this.address); // 关键：复制可变成员
        return copy;
    }
}
```

### 4.2 拷贝构造 / 工厂方法：可控、可读、可逐步演进

相比 `clone()`，拷贝构造或静态工厂往往更直观，也更容易在重构时保持兼容性。

```java
class Order {
    final long id;
    final Address address;

    Order(long id, Address address) {
        this.id = id;
        this.address = address;
    }

    static Order copyOf(Order other) {
        return new Order(other.id, new Address(other.address));
    }
}
```

### 4.3 “共享不可变对象”通常是更好的选择

如果引用成员本身是不可变对象（例如 `String`、`BigDecimal`、不可变集合），浅拷贝共享引用通常是安全的，也更省内存。

## 5. 工程实践：什么时候一定要深拷贝

- 出参对象会被外部修改（例如返回可变 `List`）：深拷贝或返回不可变视图，避免调用方“改坏内部状态”。
- 跨线程共享对象且包含可变成员：深拷贝能减少共享可变状态，但并不等同于线程安全，还需要配合正确的并发控制。
- 缓存命中返回同一对象实例：若调用方会修改对象，必须返回副本或做只读保护。

## 6. 总结

- 浅拷贝复制“值与引用”，深拷贝复制“对象图”。
- `clone()` 的默认语义是浅拷贝，深拷贝必须显式复制可变成员。
- 工程上更常用拷贝构造/工厂方法；不可变对象可直接共享引用，避免无意义深拷贝。
