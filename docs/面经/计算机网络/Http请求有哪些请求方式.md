## 1. GET (获取资源)

这是最常见的方法。它用于从服务器请求获取指定资源。

- 特点：
    - 主要用于“读取”或“查询”数据，不应该改变服务器上的数据。
    - 请求参数会附加在 URL 的末尾（例如 `?key1=value1&key2=value2`），URL 可能出现在浏览器历史、代理日志与监控中，因此不建议承载敏感信息。
    - 请求是幂等的，意味着多次发送同样的 GET 请求，其结果和只发送一次是相同的。
    - 请求是可缓存的，可以被浏览器或代理服务器缓存。

    例子：在浏览器地址栏输入网址访问网页，点击链接跳转，查看商品列表。

## 2. POST (创建资源)

用于向服务器提交数据，请求服务器创建一个新的资源。

- 特点：
    - 数据包含在请求体（Request Body）中，而不是 URL 中，因此可以发送大量数据，也避免参数直接暴露在 URL 中。
    - 传输安全取决于 HTTPS，而不是 GET/POST；敏感信息应配合 HTTPS、鉴权与脱敏日志。
    - POST 请求不是幂等的。如果连续两次提交同样的 POST 请求，服务器上可能会创建两个新的资源。
    - 请求默认是不可缓存的。

    例子：用户注册时提交表单，发表一篇新文章，下订单。

## 3. PUT (更新/替换资源)

用于向服务器发送数据，以更新或完全替换一个已经存在的资源。

- 特点：
    - 与 POST 类似，数据也包含在请求体中。
    - PUT 请求是幂等的。无论你用同样的数据发送一次还是多次 PUT 请求到同一个 URL，最终服务器上该资源的状态都是一样的。
    - 它要求客户端提供完整的资源数据，会对整个资源进行替换。

    例子：更新一个用户的完整个人资料信息（姓名、年龄、地址等全部信息）。

## 4. DELETE (删除资源)

用于请求服务器删除指定的资源。

- 特点：
    - DELETE 请求是幂等的。一次或多次删除同一个资源，最终结果都是该资源不存在。
    - 操作通常是不可逆的。

    例子：删除一篇文章，取消一个订单。

## 5. PATCH / HEAD / OPTIONS / CONNECT / TRACE

### 5.1 PATCH（部分更新）

PATCH 用于对资源做“部分修改”，常见两种语义：

- Merge Patch：提交部分字段，服务端按规则合并（工程中更常见）。
- JSON Patch：提交一组操作（add/replace/remove），语义更严格。

PATCH 是否幂等取决于接口设计：如果“同一 PATCH 重放多次结果一致”，那它就是幂等的。

### 5.2 HEAD（只要响应头）

HEAD 与 GET 语义类似，但服务端只返回响应头不返回响应体，常用于探测资源是否存在、长度、缓存相关 header 等。

### 5.3 OPTIONS（能力探测）

OPTIONS 用于查询目标资源支持哪些方法、是否允许跨域等，浏览器的 CORS 预检请求也会用到它。

### 5.4 CONNECT / TRACE（了解即可）

- CONNECT：建立隧道（常见于 HTTPS 代理）。
- TRACE：回显请求链路（安全上通常会禁用）。

## 6. 安全性与幂等性（怎么判断）

- Safe（安全）：语义上不应修改服务器状态（GET/HEAD/OPTIONS 通常是 safe）。
- Idempotent（幂等）：同一请求重复执行 N 次，最终资源状态相同（GET/PUT/DELETE 通常是幂等的）。

幂等性之所以重要，是因为网络重试不可避免：幂等接口更容易做自动重试与故障恢复。

## 7. 总结

- GET/POST/PUT/DELETE 是最常用的四类方法；PATCH/HEAD/OPTIONS 在工程中也很常见。
- 传输安全看 HTTPS 与鉴权，不是“POST 天生更安全”。
- 设计接口时优先把“语义”和“幂等性”讲清楚，便于重试、缓存与治理。

| 方法 | 主要用途 | 是否幂等（Idempotent） | 是否安全（Safe） | 数据位置 |
| --- | --- | --- | --- | --- |
| GET | 查询/获取资源 | 是 | 是 | URL |
| POST | 创建新资源 | 否（通常） | 否 | 请求体 |
| PUT | 完整更新资源 | 是 | 否 | 请求体 |
| DELETE | 删除资源 | 是 | 否 | URL |
| PATCH | 部分更新资源 | 取决于语义 | 否 | 请求体 |
| HEAD | 获取资源元数据 | 是 | 是 | URL |
| OPTIONS | 查询支持方法 | 是 | 是 | N/A |
| CONNECT | 建立隧道 | 是（通常） | 否 | N/A |
| TRACE | 回显请求 | 是（通常） | 是（通常） | N/A |
