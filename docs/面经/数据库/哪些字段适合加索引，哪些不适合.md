# 哪些字段适合加索引，哪些不适合

## 1. 结论

适合加索引的字段通常具有高选择性且频繁用于过滤/排序/连接；低选择性、频繁更新或超大字段不适合。

## 2. 适合加索引

- WHERE、JOIN、ORDER BY、GROUP BY 高频字段。
- 区分度高的列（如用户 ID）。
- 覆盖查询的组合字段。

## 3. 不适合加索引

- 取值很少的列（如性别）。
- 频繁更新且写压力大的列。
- 超长文本或很少被查询的字段。

## 4. 常见追问/易错点

- 追问：如何判断字段的选择性？

- 易错点：给所有列加索引导致写性能下降。
  - 答：常见易错点是只给结论不讲依据、边界条件与前提不清。比如适合加索引中提到：WHERE、JOIN、ORDER BY、GROUP BY 高频字段。不适合加索引中还提到：取值很少的列（如性别）。这些细节很容易被忽视。回答时应明确边界、关键步骤与适用场景，并用实例或对比验证。
