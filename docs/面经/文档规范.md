# 文档规范

## 1. 适用范围

- 本规范适用于 `D:\notes\docs\面经` 下所有 `.md` 笔记（含新建与修订）。
- 每个文件对应一个问题或主题，标题与文件名一致。
- 新建条目前先检索是否已有同主题文件，避免重复。

## 2. 文件与编码

- 编码为 UTF-8（无 BOM）。
- 行尾使用 LF，不保留行尾空格。
- 文件名保持可读，修正明显错别字；不随意更改既有术语大小写。
- 文件名建议：`{问题}.md`，简短清晰，避免无意义前缀；必要时用 `-` 连接。
- 文件名中的常见缩写统一大小写：HTTP、HTTPS、TCP、UDP、DNS、URL、URI、IP、JVM、JDK、JUC、GC、SQL、MySQL、Redis、Kafka、RabbitMQ、RocketMQ、Netty、Nginx、ZooKeeper、CAS、AQS、AOP、MVC、IoC、JWT、ORM、RDB、AOF、TTL、QPS、RBAC、ABAC、etcd。
- 目录名中的常见缩写统一大小写：Java、Spring、Redis、Agent。
- 当术语有多种写法时，优先采用官方/社区主流写法（如 `MySQL`、`ZooKeeper`）。

## 3. 标题与层级

- 一级标题：`# {问题}`，文件首行且唯一。
- 二级及以下标题必须带编号：
  - `## 1. ...`
  - `### 1.1 ...`
  - `#### 1.1.1 ...`
- 标题文本不重复编号，不使用“第X章”等格式。
- 编号按层级递增，不跳号；同级标题保持并列结构。

## 4. 正文与段落

- 段落之间空一行；列表与段落前后空一行。
- 中文标点使用全角；英文缩写与数字使用半角。
- 关键结论、要点可用 **加粗**，但避免通篇加粗。
- 单段不宜过长，尽量 3–5 句以内，必要时拆分为列表。

## 5. 列表与表格

- 无序列表使用 `-`；有序列表使用 `1.`。
- 子列表缩进 2 个空格，层级不超过 3 级。
- 表格必须包含表头与对齐行，字段名使用名词短语。
- 表格适合“对比/归纳”，不放长段文字。

## 6. 代码与命令

- 使用围栏代码块，优先标注语言（如 `java`、`shell`、`sql`）。
- 行内代码使用反引号，术语/变量可用行内代码突出。
- 命令示例尽量给出输入与预期输出的最小片段。

## 7. 内容要求

- 必须给出问题的直接回答或结论（1–3 句）。
- 视主题补充：原理、步骤、优缺点、适用场景、注意事项、示例。
- 增加“常见追问/易错点/排查思路”等加分项。
- 术语统一，避免明显错别字和前后冲突；首次出现的缩写给出全称。
- 避免“只讲定义不落地”，需要能用一句话说明“怎么用/何时用”。

## 8. 可选结构模板

- `## 1. 结论`
- `## 2. 原理/流程`
- `## 3. 关键点/注意事项`
- `## 4. 优缺点/适用场景`
- `## 5. 常见追问/易错点`
- `## 6. 示例/伪代码`

## 9. 写作自检清单

- [ ] 标题与文件名一致且唯一？
- [ ] 是否给出直接结论？
- [ ] 是否补充了原理或流程？
- [ ] 是否包含可扩展点（对比、场景、优化）？
- [ ] 是否有至少 1 条面试追问/误区？
- [ ] 术语/缩写是否统一？

## 10. AI 提示词（用于生成/优化笔记）

- 目标：生成面试可用、结构化、可扩展的答案。
- 提示词模板：

  ```text
  你是一名资深面试官+技术讲师，请围绕「{问题}」输出 Markdown 笔记：
  1) 先用 1-3 句给出结论/核心回答
  2) 原理或流程（分步骤）
  3) 关键点/注意事项
  4) 优缺点/适用场景（对比同类方案）
  5) 常见追问/易错点
  6) 示例/伪代码（可选）
  要求：术语统一、逻辑清晰、避免空话，适度延伸到实践与排查思路。
  ```
