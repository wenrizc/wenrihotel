## 1. 核心原因

- 数据在内存，避免磁盘 I/O。
- 单线程处理命令，减少上下文切换与锁开销。
- epoll/kqueue 等多路复用提升网络效率。
- SDS、跳表等专用数据结构降低复杂度。

## 2. 限制与注意

- 单线程 CPU 成为瓶颈时需分片或集群。
- 大 Key 与热 Key 会拖慢整体性能。

- 易错点：以为单线程就一定慢，忽视 I/O 与锁开销。
  - 答：常见易错点是只给结论不讲依据、边界条件与前提不清。比如核心原因中提到：数据在内存，避免磁盘 I/O。限制与注意中还提到：单线程 CPU 成为瓶颈时需分片或集群。这些细节很容易被忽视。回答时应明确边界、关键步骤与适用场景，并用实例或对比验证。
