## 1. 先判断：这是典型的外部排序问题

“1 亿数据 + 10 MB 内存”说明数据规模远超内存，无法一次性装入内存排序。标准解法是 **外部归并排序（External Merge Sort）**，核心思想是：

1. 把大文件切成可放入内存的小块，分别排序并落盘成多个有序段（run）。
2. 对多个有序段做多路归并，生成最终有序输出。

## 2. 外部归并排序的核心流程

### 2.1 生成有序段（Run Generation）

1. 分块读取：每次读取 `chunkSize` 条数据（由 10 MB 内存决定）。
2. 内存排序：用快排/归并排序等。
3. 有序落盘：写成临时文件 `run_1, run_2, ...`。

### 2.2 多路归并（K-way Merge）

归并阶段通常用最小堆（小根堆）维护每个 run 的当前最小元素：

- 每次弹出最小值写入输出。
- 再从该元素所在的 run 读入下一个元素入堆。

归并的复杂度大致是 O(N log K)，K 为归并路数（run 数量或每轮合并的文件数）。

## 3. 关键工程点（决定能不能跑快）

### 3.1 预留缓冲区，别把 10 MB 全给数组

除了存放待排序数据，还要为：

- 文件读取缓冲（减少系统调用）
- 堆结构与对象开销（避免频繁 GC）

预留空间，否则容易抖动甚至 OOM。

### 3.2 尽量顺序 I/O，减少随机读写

- run 文件写入尽量顺序写。
- 归并阶段对每个 run 使用读缓冲（例如一次读一批），避免逐元素读导致 I/O 过多。

### 3.3 合并轮数与归并路数

如果 run 太多，一次无法 K 路合并（受文件句柄/内存限制），可以：

- 先做多轮合并（两阶段/多阶段归并）
- 或增大归并路数 K（受资源约束）

import java.util.PriorityQueue;

    Node(int value, int runId) { this.value = value; this.runId = runId; }

## 5. 可选优化：如果数据有特殊性质

外部归并是通用解法，但若数据满足特殊条件可以更快：

- 值域很小：可用计数排序/桶排序/Bitmap。
- 数据近似有序：run 会更长，可减少 run 数。
- 分布式：可用 MapReduce/Spark 做分布式外部排序。

## 6. 总结

- 该题标准答案是外部归并排序：分块排序落盘 + 多路归并。
- 性能关键在 I/O：顺序读写、缓冲、合并轮数控制。
- 若值域/分布有特殊性，可以用桶/计数/Bitmap 等进一步优化。
