## 1. 分布式系统是什么

### 1.1 定义（面试可背）

分布式系统（Distributed System）是指：**一组通过网络通信的独立节点**（机器、进程、容器），对外提供**看起来像单个系统**的服务，并且需要在**部分节点/网络失败**时继续满足既定的正确性与性能目标。

关键词要点：

- 独立节点：有各自的时钟、内存、故障边界。
- 通过网络协作：网络不可避免地会延迟、丢包、乱序、分区。
- 对外像一个系统：隐藏分片、复制、故障切换等内部细节。
- 失败常态：故障不是异常分支，而是主路径的一部分。

### 1.2 “分布式”与“并发/集群/微服务”的区别

- 并发：同一台机器上多个线程/协程同时处理，多数共享内存。
- 集群：多个节点部署同一服务，重点是扩展与容灾，但不一定有“跨节点一致性协议”。
- 微服务：强调领域拆分与独立交付；是否“分布式系统问题”取决于是否涉及跨节点的状态与一致性（比如分布式事务、共识、复制）。

面试表达建议：**并发更像“同一房间多人干活”，分布式更像“多人在不同城市协作”，最大难点来自网络与故障。**

## 2. 它解决什么问题

### 2.1 横向扩展：吞吐与容量

单机受限于 CPU、内存、磁盘、网卡。分布式通过分片（Sharding）与多副本（Replication）实现：

- 吞吐提升：读写请求分摊到多节点。
- 容量提升：数据按 key 范围/哈希分布到多节点。

### 2.2 高可用：容灾与故障隔离

常见手段：

- 多副本：一个节点挂了，其他副本接管。
- 故障切换：主从切换、leader 选举。
- 多机房/多可用区：对抗机房级故障。

### 2.3 低延迟：就近访问与缓存

例如：

- CDN、边缘节点就近提供静态内容。
- 读多写少场景用多级缓存降低 P99 延迟。

### 2.4 组织与演进：团队自治与快速迭代（工程维度）

微服务 + 分布式基础设施（注册发现、配置、网关、消息）让不同团队独立演进，但同时也引入“分布式系统复杂度”。

## 3. 它带来哪些新问题（分布式的代价）

### 3.1 网络不是可靠的

你必须假设：

- 延迟不可预测（长尾严重）。
- 丢包与重传。
- 乱序、重复投递。
- 网络分区（Partition）：节点彼此不可达，但各自仍在运行。

工程结论：**要设计超时、重试、幂等、限流、熔断、降级**，否则“故障会放大成雪崩”。

### 3.2 部分失败（Partial Failure）是常态

单机系统失败多是“要么成功要么失败”。分布式系统经常是：

- A 节点认为写成功，B 节点没收到。
- 客户端超时重试导致写入重复。
- leader 已切换但旧 leader 仍接收请求（脑裂风险）。

因此要处理：

- **幂等**：同一业务操作多次执行结果一致。
- **去重**：请求 ID、事务 ID、日志序号。
- **一致性**：副本之间如何达成同一顺序与同一结果。

### 3.3 时间与顺序：没有全局时钟

不同节点的物理时钟会漂移。仅用时间戳排序会出错：

- 写入先后在不同节点看见的顺序不同。
- 回放日志时可能出现“新数据被旧时间戳覆盖”。

常见解决：

- 逻辑时钟（Lamport Clock）。
- 向量时钟（Vector Clock，用于发现并发冲突）。
- 基于共识的全序日志（Raft / Paxos 风格）。

### 3.4 一致性与可用性冲突：CAP 取舍

一旦发生网络分区，系统通常无法同时保证：

- C：对外表现像“单副本强一致”（常用语义是线性一致性）。
- A：每个请求都能在有限时间内得到响应（不要求成功，但不能无限挂起）。

CAP 的工程含义是：**你必须明确“业务正确性”与“可用性”在分区时谁优先**，并把它写进 SLA 与降级策略。

### 3.5 可观测性与调试难度陡增

分布式问题往往是“跨节点、跨线程、跨服务”的：

- 一次请求的链路很长（几十到几百跳）。
- 同一故障在不同节点表现不同。

所以必须具备：

- 全链路追踪：`trace_id`、`span_id`。
- 结构化日志：关键字段可检索。
- 指标与告警：P50/P95/P99、错误码分布、重试次数、队列堆积。

## 4. 典型组件与模式（知道名字不够，要说清作用）

### 4.1 复制与分片

- 复制（Replication）：提升可用性与读吞吐；代价是一致性协议与写放大。
- 分片（Sharding）：提升容量与吞吐；代价是跨分片查询/事务更难。

### 4.2 一致性协议与共识

- 共识（Consensus）：在可能崩溃的节点与不可靠网络中，对某个值/日志顺序达成一致。
- 常见协议：Raft、Paxos 家族（工程上常用 Raft 解释更直观）。

### 4.3 解耦与异步：消息队列

- 通过消息把强耦合调用变成异步处理，提升峰值吞吐与隔离故障。
- 但会引入：重复投递、乱序、延迟可见性，进而需要幂等与补偿。

## 5. 面试回答模板（1 分钟）

1. 分布式系统是一组通过网络协作的节点，对外像单系统，并且要处理部分失败。
2. 它主要解决扩展性与高可用问题（吞吐、容量、容灾）。
3. 代价是网络不可靠、部分失败、没有全局时钟，导致一致性、幂等、超时重试与可观测性都变得关键。
4. 工程上通常用复制/分片 + 一致性协议（如 Raft）+ 限流熔断 + 监控追踪来把系统做“可控”。
